## 2. Cross-Application Inconsistencies Identified

1. **Tabs Implementation:**
   - Ad-hoc custom `<button>` loops in `account/page.tsx` and `images/page.tsx`.
   - Different active border treatments (`border-b-2 border-[#315FEA]` vs `bg-[#315FEA]/10 text-[#315FEA]`).
   - *Fix:* Create a unified, accessible `Tabs` shared component in `components/ui/Tabs.tsx`.

2. **Confirmation Dialogs:**
   - Custom `<Modal>` structures built independently in `images/page.tsx` (Single delete, Bulk delete, Bulk publish), `ai-models/page.tsx` (Disconnect, Rotate), and `content/page.tsx` (Publish confirmation).
   - Inconsistent button placement, wording, and icon usage.
   - *Fix:* Create a standardized `ConfirmationDialog` shared component in `components/ui/ConfirmationDialog.tsx`.

3. **Page Headers & Titles:**
   - Inconsistent heading structures across pages (some use `<h1>` with `<p>`, some embed status badges directly in the heading, some lack breadcrumbs).
   - *Fix:* Create a standardized `PageHeader` component with title, optional description, badge, and action slot.

4. **Search and Filter Inputs:**
   - Leads and Images pages implement search boxes with raw inputs and custom icon positions.
   - *Fix:* Create a shared `SearchInput` component with accessible clear action and consistent 40px height.

5. **Glass and Elevation Treatment:**
   - No standardized glassmorphism utility; some components use `bg-white/80 backdrop-blur-md` while others use plain opaque backgrounds.
   - *Fix:* Define semantic glass utility tokens in `tailwind.config.ts` and `globals.css` (`glass-panel`, `glass-toolbar`, `glass-dropdown`).

6. **Social & WhatsApp Interaction Complexity:**
   - Currently buried inside `account/page.tsx?tab=integrations` with confusing reordering and encoding details.
   - *Fix:* Streamline into a dedicated, clean Business Communication workflow with live preview, direct WhatsApp test launcher, and simple social links.

## 3. Client Usability Analysis

1. **What is the business owner trying to accomplish?**
   - Run their business presence, check incoming leads, verify website content, showcase portfolio images, and communicate with customers via WhatsApp.
2. **What is the minimum information they need?**
   - High-level status (Live, Draft, New Leads, Incomplete items) and clean, direct actions (Edit, Review, Publish, Call, Chat).
3. **What internal details should be hidden?**
   - Raw database IDs, AI model parameters, technical prompt instructions, encoding strings, internal variant UUIDs, and raw stack traces.
4. **Can every workflow be completed on a mobile phone?**
   - Currently, several desktop-first cards, modals, and tab bars experience horizontal crampedness on viewports < 375px. Every screen will be guaranteed zero horizontal overflow and minimum 44px touch targets.
